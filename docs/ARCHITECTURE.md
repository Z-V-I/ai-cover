# 部署架构文档

## 完整链路

```
                      HTTPS (Cloudflare Proxy)
┌─────────┐          ┌─────────────────────────────────────┐
│ 用户浏览器│──HTTPS──▶│ music-ai.zvi.onl                    │
│         │          │   (A记录 → 8.134.50.67, proxied)     │
└─────────┘          └──────────────┬──────────────────────┘
                                    │ HTTP :80
                          ┌─────────▼──────────────────────┐
                          │  ECS (Debian 12, 2C2G)         │
                          │  8.134.50.67                   │
                          │                                │

                          │  ├── /       → 静态文件        │
                          │  └── /api/   → :5000 (反代)    │
```

## 数据流

1. 用户上传音频 (M4A/WAV/MP3, ≤60MB) → ECS Nginx → 决策层
2. 决策层用 ffmpeg 校验时长，超 5 分钟拒绝，非 WAV 格式自动转换
3. 排队检查 (≤20 人)，超限返回 HTTP 429
4. 决策层通过 frp (localhost:18081) 将音频传给 WSL2 推理层
5. 推理层加载对应模型，slicer 自动切片 (≤15s/段)，GPU 推理
6. 结果原路返回 → ECS → 用户下载

## 性能

| 指标 | 数值 |
|------|------|
| 模型加载 (首次) | ~40s |
| 模型加载 (热) | 0s |
| 186s 音频推理 | ~9s (20x 实时) |
| 端到端延迟 | ~30-60s |

## 关键技术决策

- **frp 而非 Cloudflare Tunnel**: 永久 Tunnel 虽然无限文件大小，但有延迟。frp 直连传 16MB 只需 2s。
- **1 进程 4 线程**: 避免 gunicorn 多进程共享状态问题。
- **slicer 强制 15s 分段**: 防止长无静音音频 OOM。
- **ffmpeg 格式转换**: soundfile 不支持 M4A，用 ffmpeg 统一转 WAV。
